RUM Large Payload & Uncompressed Asset Test

Backend detection (quickwit-consumer) checks:
1. http.response_content_length > 300KB (set automatically by OTel HTTP instrumentation from Content-Length header)
2. Span duration > 100ms (inherent in the span)
3. URL not a static asset (_next/static/, _next/data/, static extensions except .json)

Uncompressed Asset Detection

Backend detection (quickwit-consumer) checks:
1. mw.span.category = resource.script or resource.css
2. http.response.body.decoded_size > 512KB (fallback: http.decoded_response_content_length)
3. http.response.body.size == decoded size — no compression applied (fallback: http.response_content_length)
4. Span duration >= 300ms
5. browser.name is Chrome, Firefox, Safari, or Edge
6. Asset URL ends with .js, .css, or .json (from http.url / url.full)
7. http.response.transfer_size > 0 and >= encoded size (not cached)

Trace Issue Detection (on flush)

The RUM SDK does not send the attributes these detectors read, so this page adds them to the SDK's spans from the browser's PerformanceResourceTiming just before each span ends: network.protocol.version, http.request.fetch_start, http.request.request_start, resource.render_blocking_status, http.response.body.size, resource.type and fcp on the documentLoad span. Use Chrome (it reports renderBlockingStatus).

HTTP/1.1 Overhead: ≥ 5 overlapping HTTP/1.1 requests to one host under the documentLoad span, each queued (requestStart − fetchStart) ≥ 500ms.
Large Render Blocking Asset: blocking CSS/JS ≥ 1MB, FCP between 2s and 10s, asset load ≥ 33% of FCP.
